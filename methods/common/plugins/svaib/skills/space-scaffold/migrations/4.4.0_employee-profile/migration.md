## Что меняется

Профиль — одна форма для всех сотрудников, включая CEO. В шапке `role` и `units`, в теле раздел «Роль и зона ответственности»; шаблон — `templates/aspects/02_team/employee.md`. Профиль лежит в `02_team/` ближайшего объекта, где ведут работу с командой: `{имя-фамилия}.md`, при развороте — папка `{имя-фамилия}/` с `01_profile.md` (шаблон папки — `templates/nodes/employee/`). Узла `00_ceo/` и шаблона `nodes/ceo/` больше нет.

Личное сотрудника — только `_private/` внутри его папки в `02_team/`, одна на сотрудника. Прежние `_private/{владелец}/` в других местах переезжают туда.

В корневом `AGENTS.md` изменились две строки: пункт 2 списка в разделе «Куда и как писать» и маршрут «личное» в «Куда идти за классом вопроса». Из корневого `README.md` и `01_company/README.md` ушли упоминания личного контура CEO. Эталон новой редакции `AGENTS.md` — рядом с миграцией, предыдущий — `4.3.2_space-rules-preferences/AGENTS.md`.

Цели компании агент CEO получает теперь не по месту профиля, а по `units: [01_company]` в шапке его профиля: без этого поля после переноса CEO целей компании в контексте не увидит.

## Уже применено?

Папки `00_ceo/` нет, профиль CEO — в `02_team/` в новой форме с `role` и `units`; `_private/` есть только в папках людей в `02_team/`; две строки `AGENTS.md` совпадают с эталоном. Одного совпадения номера версии недостаточно.

## Шаги

1. Опись. Найди `00_ceo/` и все `_private/` пространства. Для каждого `_private/` установи владельца по имени вложенной папки (`_private/{владелец}/`), README или спроси. Найди ссылки на `00_ceo/` и на переносимые `_private/` во всех файлах пространства.
2. Место CEO. `02_team/` объекта, где ведут работу с командой CEO, — обычно `01_company/02_team/`. Имя папки — `{имя-фамилия}` латиницей по правилу имён шаблонов; неизвестно — спроси.
3. Собери пакет и покажи его до записи нумерованными пунктами:
   - `00_ceo/01_profile.md` → `{команда}/{имя-фамилия}/01_profile.md`: разделы прежнего профиля сохраняются текстом, раздел «Обязательства» — не переносится в профиль, а предлагается к целям и проектам, где они записаны; шапка — `title`, `role`, `units` (у CEO как минимум `01_company`); раздел «Роль и зона ответственности» по шаблону;
   - остальные файлы и папки `00_ceo/` → в ту же папку сотрудника под прежними именами; личное из них — в его `_private/`;
   - README папки сотрудника — по `templates/nodes/employee/README.md`, содержимое — фактический состав;
   - каждый `_private/{владелец}/` → `_private/` папки владельца в `02_team/`; папки владельца нет — сначала профиль `{имя-фамилия}.md` разворачивается в папку;
   - ссылки на перенесённое — на новые адреса; ссылка из `01_org-structure.md` — на новый профиль;
   - две строки корневого `AGENTS.md` — по эталону; строки о личном контуре CEO в корневом `README.md` и `01_company/README.md` — удалить;
   - правила `.gitignore` и прав хранилища для `_private/` — на новые пути до переноса материалов.
   Файл со статусом `final` требует согласия на точную правку. Неизвестную редакцию строк `AGENTS.md` не заменяй по сходству — покажи отличие.
4. Перед записью перечитай файлы; изменилось — пересобери затронутые пункты. Права доступа на новых `_private/` настраивай до переноса личного; на Google Drive проверь, что закрытие вложенной папки действует, иначе личное не переноси и назови это незавершённым.
5. Перенеси согласованное, сохраняя текст. Удаление пустого `00_ceo/` и прежних `_private/` — только после проверки, что всё перенесено.
6. Путь к профилю на сервере svaib (`workspace.profile_path` в `whoami`) у CEO и у сотрудников, чьи профили переехали, указывает на новый адрес. Обновить его может только сам человек или владелец через MCP svaib; назови это отдельным шагом, если сделать сейчас нельзя.

## Проверка результата

Условие «Уже применено?» выполнено. Ни одна ссылка пространства не ведёт в `00_ceo/` или в прежние `_private/`. Содержимое перенесено без потерь: состав файлов до и после совпадает, кроме согласованного. Агент CEO после `whoami` получает цели компании через `units`. Версию и журнал `.svaib/space.json` обновляет процедура «Обновить версию» только после успешной проверки; незавершённый перенос личного оставляет `in_progress`.
