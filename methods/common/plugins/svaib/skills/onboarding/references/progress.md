# Прогресс и отметки

Читай при выполнении этапа, показе полного пути и перед записью прогресса. Для короткого ответа о ближайшем шаге достаточно сводки из свежего `whoami`. Признаки этапов и форма ответа — `references/onboarding.md`, каталог — `references/stages.json`. Первые четыре группы и их приоритет задаёт входной `SKILL.md`.

Серверный статус — на платформе svaib. Определи контекст по ответу `whoami`: `account` — профиль аккаунта, `company` — профиль членства выбранной компании. У каждого контекста свой `onboarding` (`marks`, `audience`, `tools`, `reviewed_catalog`). В папке пространства хук подставляет компанию, к которой привязана папка. Владельцу `get_tenant` отдаёт прогресс компании, `get_user` — статус сотрудника. Читай статус перед работой и сохраняй отметки в том же контексте: подсказка на старте сессии берётся из кэша и может отставать на сутки.

## Путь человека

После проверки серверной личности и доступа каждый раз собирай путь: каталог × кто человек × отметки. Локальные файловые поручения до подключения выполняются без серверных отметок и не требуют пройти серверные зависимости каталога. Отдельного локального каталога и хранимого личного плана нет.

- **Применим:** `track` = `user`, `active`, `audiences` пуст или содержит `audience` человека, этап базовый или выбран в `tools`. Нет `audience` — владелец считается `ceo`, остальные `employee`.
- **Пройден:** отметка `done` на своём id или на любом из `replaces`. Явная отметка на новом id важнее наследованной. Зачёт через предшественника показывай с его названием; новую отметку не ставь.
- **Следующий после первых четырёх групп:** первый по `order` из применимых непройденных, не `skip`, у которого пройдены все `requires`.
- **Незнакомый id** в отметках пропускай и не трогай: его поставил более новый плагин.

Для `company`-этапов проверяй активность, зачёт и зависимости; следующий этап выбирай по задаче компании. Показывай владельцу «пройдено N из M». Если владелец просит путь сотрудника, рассчитай путь человека по ответу `get_user`.

## Результат

- **«Где я остановился»** — по форме из `references/onboarding.md`, одно следующее действие. Полный путь — по «покажи мой путь». Человеку — названия этапов, не id и не имена вызовов платформы.
- **Новое в каталоге** — `reviewed_catalog` меньше `catalog`: объясни изменения по записям `changelog` с номерами выше `reviewed_catalog`, предложи новое, запиши `reviewed_catalog`. У нового человека объяснять нечего — просто запиши номер. Объяснение этап не проходит.
- **Шаг этапа** — по поручению пройти онбординг или отдельный этап, по справке своего этапа; работу этапа, у которой есть свой скилл, делает он. Следующее разрешённое действие выполняй сам. Если нужны сведения или согласие, задай один конкретный вопрос. Шаги, которые может сделать только человек, — по одному, с проверкой после каждого.

## Отметки

- Данные setup и локальное развёртывание сами по себе не означают, что можно поставить серверные отметки `user.connect`, `user.space` или `company.launched`. После настоящего подключения заново проверь личность, применимость, зависимости и признаки существующего этапа; только затем используй обычную запись. Новые локальные ID этапов и файлы отметок не заводи.
- **Только после проверки признака закрытия, применимости и зависимостей.** Признак закрытия подтверждается одним из источников: наблюдённый результат — шаг выполнен и проверен в этом разговоре; артефакт в пространстве; строка учёта использования (`.svaib/usage/`) с проверенной принадлежностью человеку — `кто` сопоставлен с его `subject`. Учёт поддерживается в Claude Code и Codex; строка появляется с задержкой, к следующему запросу или концу сессии. Учёт использования — один из источников, он не обязателен.
- **Состояние:** достаточного свидетельства действительно нет — `unverified`; шаг должен выполнить другой человек — `waiting` с `reason` и `actor`; человек решил позже — `deferred`; этап ему не подходит — `skip`.
- **Запись** — вызови `update_me` с аргументом `onboarding.marks` и ключом повтора. В `expect` всегда передавай состояние отметки, которое ты прочитал (`null` — отметки не было), а меняя `audience` или инструменты — и их прочитанные значения: так чужая запись между чтением и записью не затрётся. При отказе `onboarding-conflict` возьми текущее состояние из ответа и покажи человеку. Вслепую запись не повторяй. Одной строкой скажи, что отметил.
- Краткая сводка показывает выборку этапов. Отсутствие в ней этапа не доказывает `null`. Если полный `onboarding.marks` недоступен в ответе инструмента, не угадывай `expect` и не пробуй запись для получения статуса; назови ограничение. Пройденную отметку повторно не записывай.
- **Этап компании** отмечает только владелец через `update_tenant` с той же формой `onboarding`. Если шаг компании сделал не владелец, скажи, что этап отметит владелец. Если один шаг подтвердил признаки и этапа человека, и этапа компании — например, первый разбор встречи владельца, — владелец ставит обе отметки.
