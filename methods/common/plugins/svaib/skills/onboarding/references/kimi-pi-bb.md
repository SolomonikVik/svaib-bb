# Kimi через Pi в BB

Pi — движок агента, который можно выбрать в BB вместо Claude Code или Codex. Используй этот путь, если сам выбрал Pi или другой движок не запускается на твоём компьютере. Сохраняем подходящее рабочее подключение.

Нужен **ключ подписки Kimi Code** из [консоли Kimi Code](https://www.kimi.ai/code/console). Ключ Kimi Open Platform относится к другому сервису. Условия подписки и оплаты — в разделе [«Подписка и ключ»](kimi-cc-bb.md#-%D0%BF%D0%BE%D0%B4%D0%BF%D0%B8%D1%81%D0%BA%D0%B0-%D0%B8-%D0%BA%D0%BB%D1%8E%D1%87); право на конкретную модель и размер контекста проверяются в твоём аккаунте. Ключ вводится только локально — в защищённое поле карточки или запрос Pi, без Telegram и текста разговора.

## 🔹 Выбери способ настройки

| Что уже есть | Ближайший шаг |
| --- | --- |
| Pi с Kimi уже отвечает в BB | Перейди к «Подключи svaib»; установка и новый вход не нужны. |
| В карточке «Настроить Kimi» можно выбрать Pi | Пройди карточку ниже. |
| Уже задан собственный запуск или профиль Pi | Помощник проверит его и сохранит рабочие настройки. |
| Выбора Pi в карточке нет | Проверь версию плагина svaib: выбор Pi опубликован в 0.7.0. Обнови плагин из того же источника или используй ручной раздел с помощником. |

На macOS 11 подтверждён запуск Pi и обнаружение в BB. Подключение модели, svaib и продолжение работы проверяются отдельно на твоём компьютере.

## 🔹 Через карточку Kimi

Эти шаги относятся к плагину svaib для BB 0.7.0 или новее с выбором Pi. Готовый агент и вход в svaib для карточки не нужны; версия плагина отличается от версии BB Desktop.

1. Открой BB и страницу svaib. Если плагина ещё нет, установи его по [инструкции подключения BB](bb-svaib.md).
2. Нажми **«Настроить Kimi»** и выбери **Pi**. Карточка использует установленный Pi; если его нет, предложит установить через BB.
3. Если рабочего входа Kimi ещё нет, вставь ключ Kimi Code в защищённое поле и нажми **«Продолжить»**.
4. Дождись проверки ответа. При ошибке продолжай с показанного шага.

Основной путь добавляет Kimi в существующий профиль Pi, сохраняя остальные подключения. Этот путь не предусматривает планового перезапуска BB. Если карточка не может безопасно подготовить этот профиль, помощник разберётся с ограничением или поможет настроить его вручную.

**Результат:** карточка подтвердила ответ Kimi через Pi. Теперь открой обычный разговор BB с Pi и той же моделью; служебная «Проверка Kimi» нужна только для короткого теста. Перейди к «Подключи svaib».

### Если нужна резервная установка

Выбирай **«Резервная установка»** только после разбора ошибки основного пути. Она готовит отдельные Pi, Node и профиль. Карточка не заменяет существующие пользовательские параметры запуска автоматически.

Этот вариант рассчитан на одну машину запуска агентов, подключённую к BB. Телефон, с которого открыт интерфейс того же BB, отдельной машиной не считается. Если машин исполнения несколько, помощник ведёт ручную настройку выбранной машины.

Чтобы применить отдельный запуск, карточка попросит полностью закрыть и снова открыть BB на машине исполнения; на Mac — выйти через ⌘Q. У браузерного BB перезапускается его сервер. Компьютер и телефон перезагружать не нужно. Затем карточка продолжит проверку с сохранённым ключом.

## 🔹 Вручную с помощником

Этот раздел нужен, пока карточка Pi недоступна или выбран ручной путь. До первого ответа модели команды выполняются на компьютере, где работает BB. Помощник даёт по одному шагу и проверяет результат. Если BB работает на другом компьютере или уже настроен собственный профиль Pi, сначала уточни это с помощником: настройки нужны именно там.

### 1. Проверь Pi

В терминале выполни:

```text
node --version
pi --version
```

Проверенный вариант — Pi **1.5.1/1.5.2** и Node **22.19 или новее**. Для macOS 11 используй ветку Node **22**. Если Pi уже запускается, переустанавливать его не нужно. Нужный Pi — [pi.dev](https://pi.dev), не Raspberry Pi Imager.

Если Node отсутствует, сначала поставь [Node.js 22 с npm](https://nodejs.org/dist/latest-v22.x/) и повтори проверку. Если отсутствует только Pi, используй **Settings → Providers → Pi → Install** в BB. При ошибке помощник разберёт её, прежде чем переходить к следующему шагу.

Запасная установка Pi при рабочем Node/npm — в терминале macOS/Linux:

```bash
npm install -g --ignore-scripts @earendil-works/pi-coding-agent@1.5.2
```

В PowerShell Windows:

```powershell
npm.cmd install -g --ignore-scripts @earendil-works/pi-coding-agent@1.5.2
```

После установки повтори `pi --version`. При `EACCES`, `Permission denied` или другой ошибке передай её помощнику без ключей; повторять с `sudo` не нужно.

### 2. Задай адрес международного Kimi

В стандартном профиле Pi открой или создай файл `models.json` в папке `~/.pi/agent` на macOS/Linux или `%USERPROFILE%\.pi\agent` на Windows. Помощник подскажет, как открыть эту папку на твоей ОС.

Для **нового** файла вставь:

```json
{
  "providers": {
    "kimi-coding": {
      "baseUrl": "https://api.kimi.ai/coding/v1"
    }
  }
}
```

Если файл уже есть, не заменяй его этим текстом: добавляется только `providers.kimi-coding.baseUrl`, остальные настройки сохраняются. При сомнении попроси помощника подготовить точную правку без секретов. Если задан `PI_CODING_AGENT_DIR`, используется его папка, а не стандартная.

### 3. Введи ключ

Если Kimi в этом профиле уже работает, сохрани вход и пропусти шаг. Для нового доступа выполни:

```text
pi auth login kimi-coding --api-key
```

Вставь ключ в появившийся закрытый запрос Pi и подтверди ввод. Не добавляй сам ключ в команду. Команда сохраняет ключ; готовность модели подтвердит следующий шаг. Для этого способа не нужны браузерный вход в Kimi и переменная `KIMI_CODE_OAUTH_HOST`.

### 4. Получи ответ в BB

Закрой прежнее окно Pi и открой новый разговор BB. Выбери **Pi**, затем доступную модель **Kimi Code**, и отправь:

> Ответь ровно KIMI_READY. Не используй инструменты и файлы.

**Результат:** в BB пришёл ответ `KIMI_READY`. Наличие модели в списке или сообщение о сохранённом ключе этот результат не заменяют. Если Pi не появился в BB, заверши текущие задачи и перезапусти приложение; для браузерного BB перезапускается его сервер, а не только вкладка.

## 🔹 Подключи svaib

После ответа модели передай агенту обычного разговора BB готовую сводку Telegram-помощника: выбран Pi, та же модель и компьютер, что уже проверено и что осталось. Сам агент продолжит по [маршруту подключения svaib](bb-svaib.md), сохраняя рабочий профиль и вход Kimi.

Агент проверяет пакет svaib для Pi, запуск хуков и отдельный вход в MCP svaib. Затем вызывает настоящий `whoami` в разговоре BB и сверяет аккаунт, с которым начата настройка. Python **3.10+**, Git и другие недостающие компоненты он проверяет и готовит сам; человеку остаются требуемые подтверждения.

**Результат:** агент сообщил проверенный аккаунт svaib и подтвердил работу плагина и хуков. После этого — выбор компании и папки, знакомство и первая полезная задача. Ответ Kimi сам по себе подключение svaib не подтверждает.

## 🔹 Если что-то пошло не так

| Что видно | Что делать дальше |
| --- | --- |
| **Install Failed**, но `pi --version` работает | Сначала перепроверь наличие Pi в BB; не запускай повторную установку наугад. |
| Pi запускается, **No models available** | Продолжи ввод ключа и проверку адреса API в том же профиле. Не переустанавливай Pi. |
| Ключ сохранён, ответа нет | Проверь, что это ключ Kimi Code, адрес API международный и в BB выбран тот же профиль. Не показывай содержимое `auth.json`. |
| Ошибка синтаксиса `models.json` | Покажи помощнику только несекретную часть `providers.kimi-coding`; он подготовит точную правку с сохранением остальных настроек. |
| В терминале работает, в BB нет | Проверь компьютер, профиль, путь к Pi/Node и новое окружение BB. Успех терминала не подтверждает BB. |
| Уже используется вход Kimi через браузер | Сохрани его. Для международного OAuth нужны оба адреса: `KIMI_CODE_OAUTH_HOST=https://auth.kimi.ai` и API из шага 2; ключ не записывается поверх рабочего входа. |
| При входе в svaib не видно терминала или страница не возвращается | Агент покажет терминал в боковой панели BB. Для локального callback нужен браузер в том же сетевом окружении, что и Pi; на виртуальном столе — браузер этого стола. Если окно входа истекло, агент запустит один повтор. |

Официальные справки: [вход в Pi и ключи провайдеров](https://pi.dev/docs/latest/providers), [команды входа](https://pi.dev/docs/latest/cli#credential-commands), [Kimi Code и отдельный Open Platform](https://www.kimi.ai/help/kimi-code/faq).
