# Подключение партнёра в BB

Выполни техническую настройку сам. Пользователю оставь вход в браузере и недоступные агенту подтверждения доверия или системных прав. Результат — проверенное подключение с именем аккаунта либо причина остановки и одно следующее действие.

Нужны работающий Claude Code или Codex в BB и доступ к серверу svaib. Поручение подключить включает недостающий методологический плагин и штатный вход по `references/native-connect.md`; предварительный вход в кабинет не нужен. Область скилла — подключение, без изменения пространства и его документов, сервера svaib, BB, прав запуска и аккаунта модели.

## Рабочее место и проверка

Определи project/environment/host/provider через `bb status --json` и `bb thread show --self --json`, сверь с переданными BB значениями и работай в этой связке. Сначала вызови настоящий read-only MCP `whoami` **текущей сессии**; работающий вход сохраняй. При ссылке на прежний разговор сравни связки и сообщи о различии: новая среда не подтверждает прежнюю.

Подключение или восстановление — `setup`, только проверка — `verify`; явно переданный BB режим имеет приоритет. `verify` сохраняет плагин/MCP и не запускает OAuth харнеса. Отдельный вход кабинета допустим через инструмент завершения уже запущенного пользователем единого подключения. Native MCP подтверждает только успешный вызов в этом разговоре: результаты другого процесса, CLI/HTTP и перечень tools его не заменяют.

Если в `setup` MCP не работает, прочитай [native-connect.md](references/native-connect.md): источник, команды, профиль и браузерный вход. Подготовку выполни сам, включая пути, конфиги и команды; callback человек не копирует. Если нужный scope установить нельзя, назови причину и останови вход до её разрешения.

В Codex после установки или обновления методологического пакета вызови `svaib_codex_hooks`: он включает доверие всем хукам svaib@svaib, сохраняя другие плагины. Затем проверь фактический запуск хуков в рабочем разговоре BB; установка и успешный MCP его не подтверждают.

## Единое подключение BB

Кабинет и партнёр входят отдельно:

1. Для незавершённого входа кабинета вызови `svaib_connect_begin`. Backend открывает браузер; при `pending` повторяй тот же инструмент. `reopenBrowser:true` используй только по просьбе открыть закрытую вкладку. Это вход кабинета, не проверка MCP.
2. В `setup` проверь native-пакет и MCP выбранного харнеса по `references/native-connect.md`. Работающую официальную установку svaib@svaib сохраняй; недостающую устанавливай из BB-комплекта с постоянным marketplace. BB и Harness выпускаются независимо и поддерживают текущую и две предыдущие minor-линии друг друга со всеми patch-версиями. Разница версий сама по себе не мешает работе и не требует переустановки, понижения версии или повторного входа. После непосредственной OAuth-команды в persistent-терминале используй `svaib_connect_wait`; после `handedOff` заверши исходный разговор. В `verify` пакет и MCP OAuth не меняются.
3. Вызови native MCP `whoami` текущего разговора. При наличии BB хук сохраняет локальное наблюдение account_id для необязательной сверки кабинета. Если аккаунты различаются, сообщи и предложи нужный вход, сохраняя работающий MCP и возможность продолжать. Это подсказка, не серверная авторизация.

В порученном онбординге после проверки плагинов, запуска хуков и native MCP прочитай `onboarding`, сразу сохрани подтверждённое подключение серверной отметкой с прочитанным `expect` и проверь ответ. Выбор папки, Screen и каркас идут дальше. Установка не подтверждает вход, неуспешная запись — сохранение прогресса.

Путь скилла раскрывай по Skill roots: alias `rN` заменяется указанным корнем. При ENOENT проверь адрес или точный путь из установленного хука; ошибка пути не позволяет пропустить скилл. Если установленный BB-плагин ещё не виден текущему разговору, используй передачу ниже.

## Передача между разговорами

Перед первым переходом собери из текущего разговора и переданного текста Telegram краткий пакет: `intent`, `scope` (`connection-only`, `onboarding` или `work-request` по фактическому поручению), известный `expectedAccountId`, `company`, `folder`, `materials`, `constraints`, `agreements`, `nextStep`. Неизвестные account/company/folder оставь незаполненными; выбор папки можно указать в nextStep. Передавай краткие факты и договорённости со ссылкой на источник, без полного транскрипта, результатов tools, URL входа, токенов, challenge/nonce и proof. Пакет не даёт прав на компанию или затирание текста; аккаунт, права и файлы проверяются перед действием. Перерыв сохраняет поручение. Пакет текущего подключения хранится отдельно от account setup.

По явному поручению подключить svaib передай пакет в `svaib_connect_start`: он привяжет источник и откроет подключение. Получив threadId, дай `@thread:<threadId>` и заверши техническую работу здесь. Повторный вызов из того же источника возвращает существующее продолжение.

Если инструмент ещё не появился после установки плагина, выполни fallback сам:

1. Проверь project/thread через `bb status --json` и `bb thread show --self --json`, ID плагина — через `bb plugin list --json`.
2. Запиши во временный JSON поля `projectId`, `threadId` и `continuation` указанной формы.
3. Вызови `bb plugin rpc call <проверенный ID> connect --input-file <файл> --json`; RPC проверит схему и откроет продолжение.

Человек не готовит JSON и не формулирует поручение заново. Источник берётся из self thread, не активного окна или панели. Если он недоступен, скажи, что договорённости не захвачены, и помоги одним действием вернуться в исходный разговор.

В `setup` используй пакет как данные. При `captured:false` восстанови ограниченную сводку именно из указанного источника через `bb thread log <ID> --limit <число>`; точное сообщение — `--message <seq>`. Передай сводку optional полем `continuation` в `svaib_connect_begin` до проверки аккаунта; свежий чат для этого не нужен. Полный журнал и значения по умолчанию не заменяют договорённости; недоступные компанию, папку и разрешения не выдумывай.

При freshVerification передай актуальную сводку optional полем `continuation` в `svaib_connect_verify` или `svaib_connect_wait`: сохрани intent/scope/expectedAccountId и все ограничения, добавь состоявшиеся договорённости. Работающий native MCP перехода не требует. Если установке/входу нужен свежий native-контекст, объясни один автоматический переход в «Партнёр svaib». После `handedOff` используй выданную ссылку, сохраняя вход и компанию; новый технический чат не нужен. Вернувшемуся в старый чат помоги перейти в существующее продолжение по одному действию.

## После подключения

После успешного `whoami` продолжай исходное поручение через `onboarding`. Следующий маршрут относится к онбордингу и подготовке пространства; проверка или восстановление входа им не расширяются. Сразу отмечай проверенные этапы, затем называй и выполняй следующее разрешённое действие либо задавай вопрос о недостающем. При паузе остановись; продолжение восстанавливай по свежему серверному статусу.

После выбора компании выясни неизвестное о прежних материалах и их расположении, проверь доступ чтением и используй готовый каркас. Для нового или недостающего согласуй структуру в разговоре или необязательном Screen и передай агенту со `space-scaffold` выбранную папку, доступные источники и согласованное. Предварительная синхронизация Git/Drive и импорт всех знаний не нужны.

Если человек выбрал Screen, в текущем проекте BB вызови `svaib_screen_open` с выбранной компанией: инструмент проверит папку и доступ. Подходящий текущий разговор сохраняй. Если нужна постоянная папка, помоги человеку выбрать её или проект штатными средствами BB; служебный каталог не предлагай и выбор за него не делай.

Screen показывает данные и пожелания; согласованное реализует и проверяет агент со `space-scaffold`. Разница версии структуры сама по себе работу не блокирует. Если BB не показывает Screen, назови ограничение и согласуй структуру в разговоре, затем подготовь файлы. Обычный онбординг не включает ремонт плагина и настроек BB: не отправляй человека искать неподтверждённую панель, разбирать исходники, править, пересобирать, переустанавливать или перезагружать плагин. Сохраняй рабочие входы, данные и выбранную папку.

После создания и чтения файлов отметь пространство. При первом проверенном появлении `AGENTS.md`, `.svaib/` и каркаса один раз предложи свежий обычный разговор в том же project/environment/folder для подключения корневых правил. Подготовь сводку: компания, поручение, ограничения и договорённости, проверенный результат и ближайший непройденный шаг; дай ссылку на текущий разговор. Новый агент читает корневые инструкции, `whoami` и marks. Это добровольное продолжение без setup/OAuth: пространство засчитывается независимо от перехода; если человек остаётся, продолжай здесь. Предложение не повторяется на следующих этапах. Дальше — первое недостающее: профиль → зона ответственности → первая полезная задача. Заполнение процесса или другого раздела вместо знакомства требует отдельного поручения.

Для отдельной диагностики кабинета установи ID BB-плагина по origin/инструкции текущего разговора и списку установленных плагинов; общий пакет — `svaib-workplace`. Вызови `bb plugin rpc call <проверенный ID> status --json`; этот статус не подтверждает native MCP. Сравнивай аккаунт по `account_id`, затем прежнему `canonical_subject_id`, затем legacy `subject_id`; tenant_id и membership subject аккаунтом не являются. Регистрация без компании допустима и не даёт company/Screen-прав. Выбор компании в кабинете не перепривязывает рабочий чат или `.svaib/platform.json`.

## Результат

«Партнёр работает» — после успешного MCP `whoami` в проверяемом разговоре. Назови, где проверено: это не подтверждает другие компьютеры, все источники, выбранную компанию, Screen или каркас. Локальная сверка аккаунтов не заменяет авторизацию.

Вне unified flow, если внешний вход завершён, текущая сессия ещё не видит инструмент, а автоматического перехода нет, подготовь короткий запрос для нового обычного разговора в той же среде и с тем же движком, со ссылкой на текущий. Если свежий разговор тоже не видит MCP, вернись к диагностике scope; повторные входы наугад не нужны. Ошибка или отмена второй стороны сохраняет работающее подключение.
